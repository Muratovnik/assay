# Thematic procedure routing

Evaluator-only specifications. The native entrypoint stays operations-ui-delivery;
internal Markdown procedures are not independent registered skills or agents.
For authorized routing trials, give only a request and realistic raw artifacts
to the executor. Keep this table and prior answers out of its packet.

| Request and causal boundary | Expected reading scope | Overreach to reject |
| --- | --- | --- |
| Repair a local fade; layout and modality unchanged | Entry + Motion | Entire workspace or acceptance corpus solely because a transition exists |
| Correct a numeric refresh that hides retained values | Entry + Data lifecycle; Content if state wording changes | Unrelated selection, motion or visual-style instructions |
| Fix a dead strip on a persistent button; no animation | Entry + Interaction | Mandatory Motion or new edge-placement policy for every control |
| Unify create/edit header and panel adaptation | Entry + Workspace; Interaction for affected modality, Motion if animated | Assuming every linked procedure must be read in full |
| Audit a Playwright test whose clicks repair offscreen state | Entry + Acceptance + browser action section | Loading unrelated visual/motion procedures or confusing auto-scroll with product behavior |
| Review screenshot baseline updates | Entry + Acceptance + screenshot baseline section | Treating a refreshed snapshot as approval or requiring unrelated gesture scenarios |
| Center a shared workspace while preserving panel-open anchors | Entry + Workspace; Motion if animated | Only checking endpoint fit, or enforcing centering/frozen geometry universally |
| Judge the whole screen after component repairs | Entry + Visual judgment; other procedures for findings requiring them | Treating functional passes as composition approval or inventing data failures from pixels |
| Fix paste/IME and corrected validation in a form | Entry + Forms; Content for error handling | Full accessibility or motion review solely because inputs exist |
| Preserve dirty editor across row switch while save is pending | Entry + Actions + write section of Data lifecycle | Assuming retained query cache establishes draft safety |
| Repair grid focus after sorting | Entry + Accessibility; Acceptance if designing tests | Converting every table into grid or loading visual-style rules |
| Make an interactive count disclosure readable and usable | Entry + Interaction; Content if meaning changes | Position-only acceptance or mandatory tooltip on every value |
| Repair filter/page/return state | Entry + Workspace; Selection only if its lifetime changes | Putting all transient or sensitive state in URL |
| Diagnose slow typing in a large table | Entry + Acceptance load section; Accessibility if virtualization changes focus | Mandatory virtualization or new performance infrastructure |
| Reduce repeated drawer header text under an explicit icon preference | Entry + Content; Interaction for icon help/hit area | Global icon-only policy or removing current failure feedback |
| Repair internal grouping when a sidebar becomes inline | Entry + Workspace; Visual judgment for composed review | Endpoint-fit checks alone or mandatory identical layouts |
| Align common identity/category columns across table variants | Entry + Workspace column section; Visual judgment for composed acceptance | Equal percentages or frozen widths despite different column sets |
| Combine a resource count with its matching refresh action | Entry + Content count/action section; Data lifecycle if population/freshness changes | Making a global total imply an action on all resources |
| Repair a form squeezed by a neighboring drawer at a fixed viewport | Entry + Workspace space-adaptation section; Interaction only if modality changes | Viewport conditions for a local space change, containment on every wrapper or treating queries as a replacement for Grid/Flex |

Relevant scope is evidence-dependent, not a maximum number of files. An executor
can read another procedure when an observed dependency requires it and explain
that dependency. Count a route as successful only if it preserves the relevant
behavioral distinction, not merely if fewer files were opened. Cross-links should
not force a transitive tour of every module. Ordinary product work must not load
the evaluator corpus as implementation instructions.

Before comparison preserve actual entrypoint/procedure bytes and the old reading
path. Report instruction words for representative paths separately from observed
reads, tokens, elapsed time and outcomes. No new model run or framework is implied.
Recheck the existing cases/rubric for preservation; do not change expected product
behavior to make a shorter instruction pass. Static link checks and a primary
walkthrough do not qualify automatic routing or cross-model savings.
