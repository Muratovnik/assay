# Thematic procedure routing

Evaluator-only specifications. The native entrypoint stays operations-ui-delivery;
internal Markdown procedures are not independent registered skills or agents.
For authorized routing trials, give only a request and realistic raw artifacts
to the executor. Keep this table and prior answers out of its packet.

Relevant scope is evidence-dependent, not a maximum number of files. An executor
can read another procedure when an observed dependency requires it and explain
that dependency. Count a route as successful only if it preserves the relevant
behavioral distinction, not merely if fewer files were opened. Cross-links should
not force a transitive tour of every module. Ordinary product work must not load
the evaluator corpus as implementation instructions.

Before comparison preserve actual entrypoint/procedure bytes and the old reading
path. Report instruction words for representative paths separately from observed
reads, tokens, elapsed time and outcomes. No new model run or framework is implied.
Recheck the existing cases/rubric for preservation; do not change expected product
behavior to make a shorter instruction pass. Static link checks and a primary
walkthrough do not qualify automatic routing or cross-model savings.
