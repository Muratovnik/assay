# Research-driven change

Carry the requested outcome across methods without losing why a change is needed,
what supports it or what was actually delivered. Own the transitions and the
end-to-end account, not another research method, planner, executor or task store.
A stage can conclude that retaining the existing solution is justified.

## Locate this request in the work

Recover the selected subject, outcome, constraints, available prior decisions and
requested endpoint: decision, plan, local change, published proposal or checked
revision. Enter at the first unresolved dependency, not always at research. A
plan-only request stops at its plan; a request for implementation and a pull
request does not end with research or an intention to publish.

Use the existing owning plan, issue or authorized notes. A short task can keep its
account in chat. For interrupted work, changed subjects or authority, use the
[planning continuation method](../implementation-planning/references/continuation.md)
to reconcile the record with the current artifact. Do not select a nearby plan
when the requested one is unresolved. Existing evidence is reusable when its
relevant premises still hold; refresh affected uncertainty, not the whole survey.

Distinguish readiness, authorization and available capability. This skill supplies
no permission to write, delegate, install, publish, merge or release. Apply the
current request and owner rules; do not add approval gates to already authorized
work. An explicitly selected workflow remains in charge: contribute missing
criteria inside it rather than starting a competing process.

## Connect results, not ritual stages

Use [stage handoffs](references/stage-handoffs.md) for a multi-stage request or a
return from an existing result. Before each consequential transition establish
its sufficient input, authorized effect and observable output. Accept a stage's
actual result, evidence and remaining gaps, not its completion label alone.
Keep one chain from need through evidence, decision, plan unit, change, check and
delivery; [evidence to change](references/evidence-to-change.md) defines those links.

Select only methods whose decisions matter:

| Decision within the active work | Criteria owner |
| --- | --- |
| Unresolved substantive comparison, sources or research sufficiency | [Evidence research](../evidence-research/SKILL.md) |
| Plan, dependencies, acceptance, contract changes or continuation | [Implementation planning](../implementation-planning/SKILL.md) |
| System boundaries, contracts or placement | [Software architecture](../software-architecture/SKILL.md) |
| Authorized changes to executable code or tooling | [Code maintenance](../code-maintenance/SKILL.md) |
| A skill's behavior, transfer or comparative evaluation | [Skill design](../skill-design/SKILL.md) |
| UI behavior or design artifacts | [Operations UI delivery](../operations-ui-delivery/SKILL.md) |
| Test design or a claim about an existing check | [Test writing](../test-writing/SKILL.md) / [test audit](../test-audit/SKILL.md) |
| A requested audit conclusion | [Independent audit](../independent-audit/SKILL.md) |

These are criteria owners, not assignments to invoke every skill or launch agents.
Keep a selected method's existing scope; return its result to this owning work
without recursively starting the lifecycle again. Reuse unchanged criteria already
in context. Editing prose in a Git repository does not by itself require code
maintenance. Ordinary authoring remains available for prose-only changes.
Delegation is optional; only after it is authorized use the existing
[route-subagents](../route-subagents/SKILL.md) policy and available client tools.
An unavailable optional method is an evidence limit, not permission to install it.

## Review, deliver and close the actual request

For feedback, verification drift or publication use
[review and delivery](references/review-and-delivery.md). Validate a finding and
return to the responsible decision, implementation or check. Do not restart every
stage or accept review advice mechanically. Keep self-review distinct from an
independent audit, and audit authority distinct from repair authority.

Report the attained endpoint against the request, its exact subject/revision,
applicable evidence and remaining work. Changed, checked, published, CI-complete,
reviewed and merged are different claims. A blocked effect leaves that part open;
continue useful authorized work without silently substituting a different outcome.
No mandatory learning document or new global rule follows from a completed task.

`references/research-basis.md` records provenance for maintainers, not mandatory
runtime reading. `evals/` contains evaluator inputs and grading criteria; never
read it while executing a user's change.
