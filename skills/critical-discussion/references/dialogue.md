# Dialogue

Use when deciding what to ask, how to respond to pushback, how to state the
verdict or whether to bring in an independent challenger.

## Questions

1. Name the gap: what is undefined, assumed or unverifiable.
2. Close it yourself when the workspace, documentation or tools can.
3. Ask the question whose answer most changes the verdict. Batch the one or two
   that truly gate the conclusion; do not fire a list.
4. Meanwhile give a provisional view: "assuming X, the idea holds / fails
   because Y". Withhold the view only when no useful one is possible.
5. Stop questioning when the next decision no longer depends on a hidden premise.

Useful kinds, used only when the gap needs them: definition ("what does X
exclude?"), assumption ("what must be true?"), evidence ("what would we see if
this were false?"), alternative ("if you could not do it this way?"),
consequence ("what does it break downstream?"), reframe ("which problem, if
solved, makes this one irrelevant?").

## Pushback

- Without a new fact, argument or constraint: keep the position, restate its
  grounds briefly and name what would change it. Do not soften it into
  agreement and do not escalate.
- With new evidence: say what changed, which earlier point no longer holds and
  which costs remain. Changing a view on evidence is the method working.
- A request to simply endorse the idea does not change the assessment. When the
  idea is sound, say so plainly; when it has a material defect, say that.

## Verdict

State the conclusion with its confidence rather than a bare yes or no:

- supported by what was examined;
- plausible, with the assumption it rests on;
- not supported, with the reason;
- undecidable with the available information, with the missing fact.

Separate what is known from what to do: a weak evidence base can still justify
a cautious choice when the costs are asymmetric. End with what would change the
verdict and the user's next decision. Close with a question only when a
decision is actually open.

## Independent challenger

A critic working from the same context tends to share its blind spots and to
anchor on the proposal. For a costly or hard-to-reverse decision, offer a review
in a separate context that receives the need, the options and the evidence, not
the current verdict. Launch it only when the user or an invoked workflow has
authorized delegation, through [route-subagents](../../route-subagents/SKILL.md).
An ordinary discussion needs no subagent.
