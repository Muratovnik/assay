# Evaluating orchestration acceptance boundaries

Use only when revising or qualifying this skill. Give an executor one selected
case's `prompt` and `context` plus the candidate skill. Keep `rubric.json` out of
the executor context. The cases are synthetic, read-only and do not authorize
delegation, task creation, repository changes or test execution.

Compare the retained pre-edit bytes and candidate under equivalent client/model
conditions. Score decision correctness, evidence fidelity, authorized effects
and final delivery. Treat a manual walkthrough as self-review, not independent
behavioral evidence. Preserve failed or ambiguous outcomes and do not rerun an
unchanged case to select a favorable answer.

The paired controls distinguish broad from narrow acceptance, a new objective
from a repair in the same epoch, and wasteful full-suite repetition from a
material change that invalidates broader coverage. Equivalent decisions can
pass; do not grade by phrase matching.

O07-O14 additionally distinguish assignment completion from subject verdict,
deliberately matching inherited settings from explicit child choices, source ownership from runtime isolation,
and a reference to a workflow from actual delegation authority. They are
prospective decision controls; file validation is not an execution result.

O15-O17 cover economical routing for a bounded task, justified extra capability
and effort for difficult reasoning, and preserving an explicit selection under
Codex's context-fork constraints. They reject both automatic parent inheritance
and unconditional selection of the cheapest call.
