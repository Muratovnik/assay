## Diagnosis

Preserve computed catalogs, version-scoped package boundaries, operational numbers and evidence totals when their role needs precision. |

Derive the supported acquisition and use route from product sources, including native integration where applicable. A genuine direct-source interface remains a valid route. |

A demonstration is sufficient when it actually teaches that same route; do not add an installation or launch sequence to a product that requires none. |

| A plausible prerequisite paragraph or diagnostic command is accepted as readiness. | A reader reaches an operation before a condition enforced by its actual execution path is established. | Associate applicable source conditions with the first dependent action. | Reading a top-level entry point is treated as a complete contract. | Conditions in selected configuration, delegated checks or a Git hook can be missed. | Follow the relevant branch and delegated checks far enough to derive applicable conditions. ## Implemented plan

1. **Repair the unit of work.** In `technical-writing/SKILL.md` and `document-design.md`, make the requested reader outcome precede the current outline, and read retained material and connected procedures during final review.
2. **Repair procedure completeness.** In `document-design.md`, derive applicable conditions from a sufficient contract or the relevant implementation path; place concrete setup or a usable handoff before the first dependent action. Apply stated adaptations to the complete resulting procedure, including intervening copying and the consumer path. Keep the associations in working evidence, not product prose.
3. **Repair content selection.** Apply omission-based contribution review to introductions, totals, examples, qualifiers and entire passages. Use the function and time reference of each passage to distinguish current guidance from preserved history. In `grounding.md`, admit a qualification only when an actual contextual claim, action or reporting duty needs it. Preserve useful precision, explanation, conditions and required notices; use no word blacklist or deletion quota.
4. **Repair product entry and source ownership.** In `readme.md` and the public template, distinguish acquisition, normal use and demonstrations; trace the canonical description producer and its generated projections.
5. **Repair verification and acceptance.** In `reader-testing.md` and `paired-pilot.md`, distinguish quoted prose from supplied readiness, full results from narrow exercises, saved output from reported actions, and ties from demonstrated improvements. Use bounded authorized checks and stop after scoped requirements hold.
6. **Evaluate before promotion.** Freeze the complete baseline and candidate, compare working condition/discovery/valid-control tasks and the real complete documentation workflow, then open one reserved pair after selection. Keep raw outputs, adverse results, measurement corrections and concrete limits. Mark the PR ready only after the final evidence and repository gates are reconciled.

Each frozen runtime version is a joint intervention. This comparison does not isolate the effect of each sentence or component. The existing runtime contains no example-specific ban on seven, Ulf, installation sections or causal explanations.

### Download, verify and restore the published evidence

Download [ZIP 1](task-completion-evidence.zip), [ZIP 2](task-completion-evidence-2.zip) and the [index](task-completion-evidence.index.json) into the same local folder. Both ZIPs are required. With Python 3.11 or later, save the following as `restore-evidence.py` there and run `python3 restore-evidence.py` from that folder. The destination must be a new or empty directory, with no `..` component or symlink in its path.

```python
import hashlib
import json
import subprocess
import sys
import tempfile
import zipfile
from pathlib import Path

names = ("task-completion-evidence.zip", "task-completion-evidence-2.zip")
index = json.loads(
    Path("task-completion-evidence.index.json").read_text(encoding="utf-8")
)
if index.get("schema") != "assay-exact-byte-evidence-v1-index":
    raise SystemExit("Unexpected evidence-index schema")
rows = index.get("archives")
if (not isinstance(rows, list) or len(rows) != 2
        or any(not isinstance(row, dict) or row.get("name") not in names
               for row in rows)):
    raise SystemExit("Index must name exactly the two published ZIPs")
by_name = {row["name"]: row for row in rows}
if len(by_name) != 2:
    raise SystemExit("Duplicate ZIP name in evidence index")
primary_record = by_name[names[0]]
if (index.get("archive_sha256") != primary_record.get("sha256")
        or index.get("archive_bytes") != primary_record.get("bytes")):
    raise SystemExit("Primary ZIP fields disagree in evidence index")

primary, second = (Path(name).absolute() for name in names)
for archive in (primary, second):
    record = by_name[archive.name]
    with archive.open("rb") as stream:
        actual_sha256 = hashlib.file_digest(stream, "sha256").hexdigest()
    if (actual_sha256 != record["sha256"]
            or archive.stat().st_size != record["bytes"]):
        raise SystemExit(f"ZIP identity does not match index: {archive.name}")

# Both complete ZIPs are verified before extracting the bundled restore code.
destination = Path("task-completion-restored").absolute()
with tempfile.TemporaryDirectory(prefix="assay-evidence-restore-") as temporary:
    helper = Path(temporary) / "assemble.py"
    with zipfile.ZipFile(primary) as verified_primary:
        helper.write_bytes(verified_primary.read("assemble.py"))
    subprocess.run(
        [sys.executable, "-B", str(helper), "restore", str(primary),
         str(destination), "--part", str(second)],
        check=True,
    )
```

The script verifies both whole files, extracts `assemble.py` only from the verified primary, then invokes `restore PRIMARY DEST --part SECOND`. The restore helper rejects unsafe paths, duplicate members across volumes, symlinks and invalid member types; it requires metadata in the primary and verifies every retained blob's length and hash before writing. A successful command reports `restored_files`. It does not run saved products or tests.
