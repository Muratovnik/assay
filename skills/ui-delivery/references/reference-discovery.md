# Reference discovery

Use before choosing a custom implementation for new substantial UI or an
unfamiliar pattern without sufficient reference evidence. First inspect the
user's supplied references, product constraints and existing design system.
Reuse still-applicable evidence; a local repair against an established system
does not need a fresh external survey.

## Search by the unresolved question

- For visual direction, explore suitable examples such as
  [Refero Styles](https://styles.refero.design/). Extract hierarchy, density,
  typography, component roles and adaptation rules that serve this audience.
  An exported design guide or token set is an interpreted reference, not the
  product's authoritative specification.
- For a component, uncertain terminology or alternative implementations, use
  sources such as [The Component Gallery](https://component.gallery/). Compare
  the relevant pattern and follow its links to the owning design system and
  primitive documentation. Check fit with the actual stack and interaction;
  catalog popularity or a matching name does not establish that fit.
- For a journey, failure or recovery state, inspect real product flows and the
  relevant owner behavior. A style page or isolated component example cannot
  establish the sequence, persistence or permitted actions.

These catalogs are discovery routes, not dependencies or mandatory providers.
Use available primary sources when a route is unavailable. Distinguish appearance
from behavior and verify the latter through the owning primitive, product contract
and applicable accessibility guidance.

## Return a decision before implementation

Keep the research bounded by the question. Return the relevant source and version
or access date, the useful mechanism, its fit and limitations, whether to adopt,
adapt or reject it, and the observation needed to validate that choice. Use the
existing task or decision record; do not create another research ledger or collect
examples without a decision they inform. Sufficient existing evidence can settle
the question without new browsing.

When delegation is already authorized, use available
[delegation planning](../../route-subagents/references/delegation-planning.md)
to assign this bounded research before its dependent design decision. The primary
consumes its result before custom implementation; delegation authority and routing
stay with that method. Without delegation authorization, research locally.

Use [reuse and migration scope](../../code-change/references/reuse-and-migration.md)
for selecting and integrating existing mechanics. This procedure retains the
reference question and UI adaptation; visual judgment, component contracts and
journey acceptance remain with their existing procedures. Research alone does
not authorize installing services, copying a catalog or expanding the product.
