# assay

Переиспользуемые методы для кодовых агентов: восемь навыков и два профиля
агентов для Claude Code, Codex, Cursor и Gemini CLI.

```text
/plugin marketplace add Muratovnik/assay
/plugin install assay@assay
```

Assay — это проба на состав: испытание того, из чего вещь сделана на самом деле.
У методов здесь общая установка: сказать, что проверено, что из этого следует и
что не следует.

> [!NOTE]
> Навык инструктирует агента, а некоторые навыки здесь содержат скрипты, которые
> агент может запустить. Читайте то, что устанавливаете, — и отсюда, и откуда
> угодно ещё.

Английская версия канонична. Перевод покрывает установку и состав; вывод команд,
имена правил и ключи конфигурации не переводятся.

## Установка

| Клиент | Команда | Проверено |
| --- | --- | --- |
| Claude Code | `/plugin marketplace add Muratovnik/assay`, затем `/plugin install assay@assay` | да |
| Любой поддерживаемый агент | `npx skills add Muratovnik/assay` | да |
| Codex | `codex plugin marketplace add Muratovnik/assay`, затем установка через `/plugins` | по документации |
| Cursor | `npx skills add Muratovnik/assay -a cursor` | по документации |
| Gemini CLI | `gemini skills install https://github.com/Muratovnik/assay.git --consent` | по документации |

**Проверено** означает, что путь установки был выполнен против этого
опубликованного репозитория, а установленные файлы сверены байт в байт.
**По документации** означает, что он следует документации клиента, но здесь не
запускался. После установки начните новую сессию: клиенты читают свои каталоги
навыков при запуске.

CLI навыков покрывает Claude Code, Codex, Cursor, OpenCode «и ещё 75» по
собственному счёту. Для Codex его глобальная установка пишет в `~/.codex/skills/`,
которого нет в актуальной документации Codex среди корней навыков: ставьте в
проект либо используйте установщик ниже.

Подробности по клиентам, удаление и обновление — в
[руководстве по установке](docs/ru/install.md).

<details>
<summary><b>Установщик симлинков</b> — профили агентов и правки, действующие сразу</summary>

Плагины ставят навыки. Два профиля агентов, а также режим, в котором ваши правки
чекаута действуют без переустановки, даёт собственный установщик репозитория:

```text
git clone https://github.com/Muratovnik/assay.git
cd assay
python -m pip install -r requirements-tools.txt
python tools/assay.py plan
python tools/assay.py install-links
```

`plan` ничего не пишет. Он печатает каждую цель, которую создал бы, и точную цель
отката для каждой. `install-links` связывает `~/.agents/skills/<имя>` с этим
чекаутом и рендерит адаптеры профилей, предварительно проверяя весь план: реальный
каталог, чужая ссылка или изменённый адаптер останавливают запуск до первой записи.

В Windows создание симлинка на каталог требует соответствующего права, обычно
режима разработчика или повышенных привилегий. Установщик отказывается работать
без него и не подменяет вызов оболочкой.

</details>

## Что внутри

Навык срабатывает сам, когда задача совпадает с его описанием. Каждая строка
ведёт к инструкциям, которые агент действительно прочитает.

| Навык | Когда применять | Когда не нужен |
| --- | --- | --- |
| [code-maintenance](skills/code-maintenance/SKILL.md) | Изменение затрагивает структуру кода, общую логику или инструменты | Правка текста или аудит без изменений |
| [test-writing](skills/test-writing/SKILL.md) | Нужно написать или починить тесты по контракту | Надо лишь прогнать готовый набор или объяснить тестирование |
| [test-audit](skills/test-audit/SKILL.md) | Кто-то утверждает, что набор защищает от регрессий | Вы пишете тесты сами или просто их запускаете |
| [independent-audit](skills/independent-audit/SKILL.md) | Изменение, релиз или миграцию надо сверить с исходным заданием | Нужно внести правку: этот метод ничего не чинит |
| [evidence-research](skills/evidence-research/SKILL.md) | Важное утверждение требует источников и их сверки | Ответ находится одним запросом |
| [operations-ui-delivery](skills/operations-ui-delivery/SKILL.md) | Операционный интерфейс нужно спроектировать, починить или разобрать | Работа только на бэкенде |
| [route-subagents](skills/route-subagents/SKILL.md) | Делегирование уже разрешено и его надо ограничить | Разрешения не было: параллельность сама по себе не разрешение |
| [skill-design](skills/skill-design/SKILL.md) | Навык срабатывает не там, или метод нужно оценить | Правка метаданных или рутинное написание содержимого |

Два профиля агентов — это границы возможностей, а не роли. `evidence-reviewer`
разбирает замороженный пакет через доказательный инструмент только на чтение и
выдаёт вердикт; `official-docs-researcher` отвечает на один ограниченный вопрос
по первичной документации. Ни один не закрепляет модель.

Детали лежат уровнем ниже: `SKILL.md` остаётся коротким и уводит в `references/`
только когда задача требует глубины, поэтому неиспользуемый метод почти не
занимает контекст.

## Требования

Навыкам не нужно ничего: это Markdown. Python 3.11 или новее и закреплённый
парсер YAML из `requirements-tools.txt` нужны для собственных инструментов и
гейтов репозитория.

`route-subagents` может опционально сверяться с данными бенчмарков при выборе
модели через локальный MCP-сервер из `skills/route-subagents/scripts/`. Он
подключается вами вручную, и навык работает без него.

## Доверие и безопасность

Скрипты здесь принимают явные пути и ничего не ставят в вашу среду сами, но это
утверждение стоит проверить, а не принять на слово.

Ничего не отправляется наружу: ни телеметрии, ни учётной записи, ни сетевых
вызовов, кроме опционального сервера бенчмарков, который вы регистрируете сами.

Эти методы читают репозитории, документацию, а исследовательский — ещё и
веб-страницы. Такое содержимое — данные, а не инструкции, и методы так и говорят,
но никакая инструкция не даёт гарантии. Проверяйте то, что агент предлагает после
чтения неподконтрольного вам источника. Об уязвимости сообщайте приватно:
[SECURITY.md](SECURITY.md).

## Как это проверяется

`python tools/check.py --all` прогоняет все гейты: структуру исходников,
модульные тесты, фикстуру совместимости, сгенерированную опись, данные оценки,
отрендеренные клиентские манифесты и набор проверок пакетов аудита. Непрерывная
интеграция запускает ту же команду на Linux и Windows, плюс аудит публикации и
валидатор манифестов плагина Claude.

Модель в CI не запускается, и ни у одного навыка нет оценки. Что именно
устанавливают каталоги `evals/`, а что нет, написано в
[docs/evaluation.md](docs/evaluation.md) (на английском).
