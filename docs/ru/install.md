# Установка assay

Какой путь выбрать, зависит от клиента и от того, нужны ли вам профили агентов
вместе с навыками. Все они ставят один и тот же источник.

[English](../install.md) · **Русский** · [简体中文](../zh-CN/install.md)

Английская версия канонична. Вывод команд, имена правил и ключи конфигурации не
переводятся.

## Что проверено, а что нет

Путь для Claude Code и путь через CLI навыков были выполнены против
опубликованного репозитория, а установленные файлы сверены байт в байт. Пути для
Codex, Cursor и Gemini CLI следуют документации этих клиентов, но здесь не
запускались. Это различие сохранено намеренно: библиотека, которая просит
различать проверенное и задокументированное, обязана делать это сама.

## Claude Code

```text
claude plugin marketplace add Muratovnik/assay
claude plugin install assay@assay
```

Эквиваленты через слэш-команды: `/plugin marketplace add Muratovnik/assay` и
`/plugin install assay@assay`. Добавьте `--scope project`, чтобы поставить для
одного репозитория, а не для учётной записи; закрепить релиз можно тегом в имени
маркетплейса: `Muratovnik/assay@v0.2.0`.

После установки начните новую сессию. Навыки появятся под своими именами, а два
профиля агентов приходят вместе с плагином.

## Codex

```text
codex plugin marketplace add Muratovnik/assay
```

Затем откройте `/plugins` в CLI и установите assay из этого маркетплейса. После
этого перезапустите Codex.

Codex читает навыки из `.agents/skills` в проекте, поднимаясь до корня
репозитория, и из `$HOME/.agents/skills` для учётной записи. Его определения
агентов лежат в `~/.codex/agents/*.toml`, куда путь через плагин не пишет: за
профилями используйте установщик симлинков ниже.

## Любой агент через CLI навыков

```text
npx skills add Muratovnik/assay
```

Добавьте `-a claude-code` или `-a codex`, чтобы нацелиться на один клиент, `-g`
для глобальной установки вместо проектной и `--skill <имя>`, чтобы взять один
метод вместо всей библиотеки.

Одна оговорка, которую стоит знать: для Codex глобальная установка этого CLI
пишет в `~/.codex/skills/`, а текущая документация Codex не перечисляет этот путь
среди корней навыков. Если после установки Codex их не видит, ставьте в проект
либо используйте установщик симлинков.

## Gemini CLI

```text
gemini skills install https://github.com/Muratovnik/assay.git --consent
```

Gemini читает `~/.agents/skills` и `.agents/skills` как псевдонимы собственных
корней навыков, поэтому установщик симлинков работает и там.

## Cursor

```text
npx skills add Muratovnik/assay -a cursor
```

Cursor хранит личные навыки в `~/.cursor/skills/`, и CLI навыков знает этот путь.
Импорт репозитория средствами самого Cursor идёт через командный маркетплейс в
Dashboard и предназначен для администратора команды, а не для одиночной
установки.

## Установщик симлинков

Используйте его, когда нужны профили агентов, или когда вы правите чекаут и
хотите, чтобы изменения действовали сразу.

```text
git clone https://github.com/Muratovnik/assay.git
cd assay
python -m pip install -r requirements-tools.txt
python tools/assay.py plan
python tools/assay.py install-links
```

`plan` ничего не пишет. Он печатает для каждой цели, что именно создал бы и какой
была бы точная цель отката; `--json` даёт то же самое структурированным выводом, а
`--home` направляет весь план в изолированный каталог для сухого прогона.

Затем `install-links` создаёт:

```text
~/.agents/skills/<имя>   -> <чекаут>/skills/<имя>
~/.claude/skills/<имя>   -> ~/.agents/skills/<имя>
~/.codex/agents/<профиль>.toml   отрендерен из profiles/<профиль>.json
~/.claude/agents/<профиль>.md    отрендерен из profiles/<профиль>.json
```

Сначала проверяется весь план целиком. Реальный каталог, чужая ссылка, изменённый
адаптер или родитель, являющийся точкой повторного разбора, останавливают запуск
до первой записи.

**В Windows** создание симлинка на каталог требует соответствующего права, обычно
режима разработчика или терминала с повышенными привилегиями. Установщик
отказывается работать без него и не подменяет вызов командной оболочкой.

## Удаление

```text
python tools/assay.py uninstall-links
```

Удаляются только записи, у которых цель ссылки или отрендеренные байты до сих пор
точно совпадают с текущим планом. Всё, что вы поменяли руками, остаётся на месте и
попадает в отчёт: удаление не может молча отбросить вашу правку.

Для путей через плагины используйте штатное удаление клиента: `claude plugin
uninstall assay@assay` или менеджер плагинов вашего клиента.

## Обновление

Заберите новую ревизию и запустите установщик снова. Если между ревизиями
изменились адаптеры профилей, обновление делается в два шага и в таком порядке:

```text
# из ревизии, создавшей текущие адаптеры
python tools/assay.py uninstall-links
# затем из новой ревизии
python tools/assay.py install-links
```

Это важно, потому что удаление снимает только байты, которые узнаёт. Запуск из
новой ревизии после смены адаптеров оставит старые на месте, и убирать их
придётся вручную.

Перед любым из этих шагов сохраните копию существующих байтов адаптеров и целей
ссылок где-то вне управляемых каталогов. Этот внешний снимок и есть путь отката;
файл состояния рядом с установкой им не является.

То же обновление по шагам, вместе с тем, что сохранить заранее и как откатиться,
разобрано в [Обновлении symlink-установки](how-to/upgrade-linked-install.md).
