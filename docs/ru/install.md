# Установка assay

`route-subagents` поддерживает настраиваемый советчик маршрутизации: по умолчанию
`native-economy` использует подходящую экономичную модель текущего клиента; Jev
включается отдельно с разрешением внешней передачи. Config v1 сохраняет прежнюю
работу с benchmark evidence. Миграция v2 создаёт отдельный файл; нативный режим
не требует SDK или ключа Jev. Установка ссылок навыков не меняет регистрацию MCP.
Настройка, переподключение, история и откат описаны в
[руководстве RoutingAdvisor](../../skills/route-subagents/references/routing-advisor.md).
Локальные проверки контрактов не доказывают качество модели или экономию квоты.

Какой путь выбрать, зависит от клиента и от того, нужны ли вам профили агентов
вместе с навыками. Все они ставят один и тот же источник.

[English](../install.md) · **Русский** · [简体中文](../zh-CN/install.md)

Английская версия канонична. Вывод команд, имена правил и ключи конфигурации не
переводятся.

## Актуальные границы поставки

Напоминания плагинов Claude Code/Codex требуют Python 3.11+ как `python`;
skills CLI и `install-links` хуки не устанавливают. Плагин Claude уже содержит
оба профиля. Полный набор сохраняет связи между методами; отдельный навык не
обещает все дополнительные критерии. `assay-optional-skills` — метаданные
проверок Assay, а не механизм автоматической установки. Историческая проверка
файлов не доказывает загрузку или поведение текущей версии. См.
[матрицу поставки](../install.md#installation-surfaces).

## Автоматические напоминания о навыках

Плагин для Codex и Claude Code включает
[`hooks/hooks.json`](../../hooks/hooks.json), создаваемый `tools/assay.py render`.
При старте, возобновлении и после сжатия контекста он напоминает применять
подходящие навыки. Перед запуском субагента приходит напоминание об обязательном
`route-subagents`, осознанном выборе модели/effort и минимальном контексте.
Это относится и к заменам исполнителей, и к проверяющим.

Нужен Python 3.11+ под командой `python` в среде клиента. Обработчик использует
только стандартную библиотеку, не вызывает модели или сеть, не читает историю
и не меняет настройки. Каждое событие добавляет меньше 1 000 символов контекста;
это небольшой, но ненулевой расход контекста. Тайм-аут — пять секунд.
Отключение или удаление плагина убирает его напоминания.

После установки или обновления начните новую сессию. В **Codex** просмотрите и
подтвердите доверие текущему определению hooks Assay через механизм клиента:
установка сама этого не делает. Отключённые hooks и политика managed-only
препятствуют запуску. В **Claude Code** проверьте события `SessionStart` и
`PreToolUse` от Assay в `/hooks`; ошибки исполнения смотрите в диагностике hooks.
См. документацию [Codex](https://learn.chatgpt.com/docs/hooks) и
[Claude Code](https://code.claude.com/docs/en/hooks).

**CLI навыков и `install-links` не подключают hooks плагина.** Для напоминаний
используйте установку плагина. Assay не правит личный `AGENTS.md`. Для других
клиентов сохраняется обычное обнаружение навыков; эти события предусмотрены
для Codex и Claude Code с поддержкой hooks.

Это напоминания, а не принудительный контроль: pre-tool контекст не задерживает
уже выбранный запуск для пересмотра моделью, а отдельные пути инструментов могут
обходить hooks. Обработчик не разрешает делегирование и не меняет аргументы или
модели. Локальные тесты проверяют события и команды, но не обнаружение клиентом,
соблюдение навыков или экономию квоты. Исторические наблюдения не подтверждают
работу hooks в текущей версии клиента и пакета.

Проверка без запуска модели из checkout:

```text
python -B -m unittest tools.test_skill_reminder
```

Если записей нет, проверьте, включён ли полный плагин с новой доработкой, а не
только ссылки навыков. При ошибке исполнения проверьте `python --version` в
среде клиента и его диагностику hooks. Успешный тест обработчика не означает,
что клиент подключил плагин и доверяет ему.

## Claude Code

```text
claude plugin marketplace add Muratovnik/assay
claude plugin install assay@assay
```

Эквиваленты через слэш-команды: `/plugin marketplace add Muratovnik/assay` и
`/plugin install assay@assay`. Добавьте `--scope project`, чтобы поставить для
одного репозитория, а не для учётной записи; закрепить релиз можно тегом в имени
маркетплейса: `Muratovnik/assay@v0.2.0`.

После установки начните новую сессию. Навыки появятся под своими именами, а два
профиля агентов приходят вместе с плагином.

## Codex

```text
codex plugin marketplace add Muratovnik/assay
```

Затем откройте `/plugins` в CLI и установите assay из этого маркетплейса. После
этого перезапустите Codex.

Codex читает навыки из `.agents/skills` в проекте, поднимаясь до корня
репозитория, и из `$HOME/.agents/skills` для учётной записи. Его определения
агентов лежат в `~/.codex/agents/*.toml`, куда путь через плагин не пишет: за
профилями используйте установщик симлинков ниже.

## Любой агент через CLI навыков

```text
npx skills add Muratovnik/assay
```

Добавьте `-a claude-code` или `-a codex` для выбора клиента, `-g` для глобальной
установки. `--skill '*'` выбирает весь набор; `--skill <имя>` — один навык без
автоматической установки соседних методов.

Проверьте путь, показанный вашей версией CLI, по актуальной документации клиента.
При пропуске обнаружения используйте поддерживаемую проектную установку или
явную схему симлинков ниже; не создавайте дополнительные псевдонимы наугад.

## Gemini CLI

```text
gemini skills install https://github.com/Muratovnik/assay.git --consent
```

Gemini читает `~/.agents/skills` и `.agents/skills` как псевдонимы собственных
корней навыков, поэтому установщик симлинков работает и там.

## Cursor

```text
npx skills add Muratovnik/assay -a cursor
```

Cursor хранит личные навыки в `~/.cursor/skills/`, и CLI навыков знает этот путь.
Импорт репозитория средствами самого Cursor идёт через командный маркетплейс в
Dashboard и предназначен для администратора команды, а не для одиночной
установки.

## Установщик симлинков

Используйте его, когда нужны профили агентов, или когда вы правите чекаут и
хотите, чтобы изменения действовали сразу.

```text
git clone https://github.com/Muratovnik/assay.git
cd assay
python -m pip install -r requirements-tools.txt
python tools/assay.py plan
python tools/assay.py install-links
```

`plan` ничего не пишет. Он печатает для каждой цели, что именно создал бы и какой
была бы точная цель отката; `--json` даёт то же самое структурированным выводом, а
`--home` направляет весь план в изолированный каталог для сухого прогона.

Затем `install-links` создаёт:

```text
~/.agents/skills/<имя>   -> <чекаут>/skills/<имя>
~/.claude/skills/<имя>   -> ~/.agents/skills/<имя>
~/.codex/agents/<профиль>.toml   отрендерен из profiles/<профиль>.json
~/.claude/agents/<профиль>.md    отрендерен из profiles/<профиль>.json
```

Сначала проверяется весь план целиком. Реальный каталог, чужая ссылка, изменённый
адаптер или родитель, являющийся точкой повторного разбора, останавливают запуск
до первой записи.

**В Windows** создание симлинка на каталог требует соответствующего права, обычно
режима разработчика или терминала с повышенными привилегиями. Установщик
отказывается работать без него и не подменяет вызов командной оболочкой.

Если в Claude Code уже стоит плагин, он сам поставляет навыки и оба профиля, и
записи для Claude показали бы каждый навык дважды. Добавьте `--client codex` к
`plan`, `install-links` и `uninstall-links`, чтобы работать только с записями
Codex, или `--client claude` — только с записями Claude. Ссылка Claude на навык
ведёт через ссылку Codex, поэтому установка одного Claude требует готовых ссылок
Codex, а удаление одного Codex отклоняется, пока остаются ссылки Claude. Убрать
записи Claude из существующей установки можно командой
`python tools/assay.py uninstall-links --client claude`.

## Удаление

```text
python tools/assay.py uninstall-links
```

Удаляются только записи, у которых цель ссылки или отрендеренные байты до сих пор
точно совпадают с текущим планом. Всё, что вы поменяли руками, остаётся на месте и
попадает в отчёт: удаление не может молча отбросить вашу правку.

Для путей через плагины используйте штатное удаление клиента: `claude plugin
uninstall assay@assay` или менеджер плагинов вашего клиента.

## Обновление

Заберите новую ревизию и запустите установщик снова, сохраняя на каждом шаге тот
же выбор `--client`. Если между ревизиями
изменились адаптеры профилей, обновление делается в два шага и в таком порядке:

```text
# из ревизии, создавшей текущие адаптеры
python tools/assay.py uninstall-links
# затем из новой ревизии
python tools/assay.py install-links
```

Это важно, потому что удаление снимает только байты, которые узнаёт. Запуск из
новой ревизии после смены адаптеров оставит старые на месте, и убирать их
придётся вручную.

Перед любым из этих шагов сохраните копию существующих байтов адаптеров и целей
ссылок где-то вне управляемых каталогов. Этот внешний снимок и есть путь отката;
файл состояния рядом с установкой им не является.

То же обновление по шагам, вместе с тем, что сохранить заранее и как откатиться,
разобрано в [Обновлении symlink-установки](how-to/upgrade-linked-install.md).
