# 升级符号链接安装

[English](../../how-to/upgrade-linked-install.md) ·
[Русский](../../ru/how-to/upgrade-linked-install.md) · **简体中文**

英文版本为准。命令输出、规则名称与配置键不作翻译。

如果你是用符号链接安装器把 assay 装在某个检出目录里的——即
`python tools/assay.py install-links`——现在想把同一份安装迁移到该检出的更新版本，
这一页就是给你的。它假定你会用 `git` 和终端，并且知道自己的检出在哪里。它不涉及
插件安装或技能 CLI 安装：那两条路径见[安装 assay](../install.md)，符号链接安装在
底层如何工作见 [assay 的组成方式](../architecture.md)。

**动手之前：**先把现有的适配器字节与链接目标复制到受管目录之外。万一升级出问题，
这份副本是你唯一的退路。安装目录旁边的状态文件不是它的备份。

## 起始状态

- assay 通过 `install-links` 安装在这个检出目录中，版本即当前检出的版本。
- 受管目标就是 `install-links` 创建的那些：
  ```text
  ~/.agents/skills/<name>
  ~/.claude/skills/<name>
  ~/.codex/agents/<profile>.toml
  ~/.claude/agents/<profile>.md
  ```
- 你希望迁移到同一检出的更新版本，不留下任何旧版本的适配器文件，并且在出问题时
  能够撤销这次改动。

## 步骤

### 1. 保存当前适配器的副本

在执行下面任何命令之前，把上述四个目标位置的当前内容复制到这些目录树之外——例如
同一台机器上的另一个目录。文件字节与链接目标都要保留；需要回滚时，你要恢复的就是
这份快照。

### 2. 在当前所处的版本上执行卸载

仍停留在当前版本上（先不要拉取新代码），执行：

```text
python tools/assay.py uninstall-links
```

只有链接目标或渲染字节仍与该版本会安装的内容完全一致的条目才会被移除。你手工改动
过的内容会被保留并列入输出，而不会被覆盖。这一步要在切换版本*之前*执行：
`uninstall-links` 只认得自己这个版本产生的字节，若改从新版本执行，旧的适配器会留在
原处，只能手工清理。

### 3. 把检出切换到新版本

按你平时使用 `git` 的方式拉取或检出目标版本。如果 `requirements-tools.txt` 有变化，
请按安装指南所述重新执行 `python -m pip install -r requirements-tools.txt`。

### 4. 从新版本执行安装

```text
python tools/assay.py install-links
```

如果想先预览将要发生什么，`python tools/assay.py plan` 不写入任何内容——它只报告每个
目标将会变成什么——而 `--home` 可以把整个计划指向一个隔离目录用于试运行。

`install-links` 会在写入任何内容之前预检整个计划。对以下四种情况——本该是链接的位置
出现了真实目录、外来链接、被修改过的适配器，或作为重解析点的上级目录——它都会在第一
次写入之前中止整次运行。该检查覆盖的是这些具名情况；它顺利通过并不等于普遍保证别处
没有写入过任何东西。

**在 Windows 上**，创建目录符号链接需要相应权限（通常是开发者模式或提升权限的
终端）。缺少该权限时安装器直接失败——它不会退回到调用 shell 命令来绕过限制。

## 结果

第 4 步完成后，四个目标位置持有新版本的链接与渲染出的适配器，上一个版本的适配器
文件一个都不剩。所创建内容的完整清单见
[assay 的组成方式](../architecture.md#清单)。

## 如果出了问题

把第 1 步保存的文件与链接目标恢复到原来的位置。不要把旧快照的字节与新版本的注册
混在一起——要整份恢复这个快照。

## 限制

- 第 4 步的预检只拒绝上述四种具名情况；它并不保证其他任何失败方式都不会留下已写入
  的内容。
- 你对链接或适配器做过的手工改动（偏移）会被 `uninstall-links` 与 `install-links`
  保留并报告，不会被悄悄丢弃——但这也意味着这类偏移可能导致预检拒绝，需要你手工
  处理。
